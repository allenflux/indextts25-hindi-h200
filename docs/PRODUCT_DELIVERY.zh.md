# IndexTTS 2.5 Hindi 产品交付验收记录

本记录对应从纯 attention LoRA 导出的真实完整 GPT。目标是在 RTX 5090 上沿用现有 T8 工作流增加 Hindi，并用可恢复的版本切换交付。每项实际结果与[验收方案 v1.0](REPLACEMENT_ACCEPTANCE.md)逐项对应。

## 交付决策

完整 GPT 候选通过权重审计、FP32 前向对照和 5090 固定短句三轮切换。Hindi TEST 的覆盖与质量未达交付门槛。正式换模由目标工作流、语音质量、旧语回归与运维演练共同放行。**当前生产放行状态为 HOLD。** 先用 HI 独立实例逐步验证。若部署方式为全量切换，ZH、EN、JA、ES、AR 分别达到非劣效门槛之后才进入生产试运行。当前历史 best100 及其音频证据保留独立身份。

## 实际核验

最终验收代码的本机 CPU 全量回归为 407/407 通过，耗时 66.075 秒。模型权重与图执行的结果以下列实物回执为准。

### 参数与模型前向

- 独立 CPU 审计在 25.058 秒内检查实际官方容器的 456 个张量。48 个目标 attention 权重均变化且与独立 FP32 公式逐位一致，其余 408 个张量逐位相同。审计另核原始、目标和适配器字节及 provenance 保护摘要。报告 SHA256 `f135292f5418600e3276f7c79232f3bfcb190540ed761defaa4651ea154a93cd`。
- 完整预训练模型的 FP32 前向对照已执行 3/3。按冻结 validation 特征长度选短、中、长三个固定样本，语义 code 长度为 130、270 和 393。原版＋未合并 A/B 与完整 GPT 的 logits/loss 均满足固定 `rtol=atol=1e-4` 的组合容差。两路预测 argmax 互相逐位一致，两路标签 targets 互相逐位一致。
- 三条原始报告 SHA256 依顺序为 `8feed19c14eb97f7f1a130178a9e5c2536949354115c6ab28952048b592e100e`、`ed833993e9fbef92e8f1bffb045977e6a9ea009f381105ea00203a82dbedc9a0`、`26d06252842456288287bc5b8c62017514ce4bdc011a62c2b60d28b012127efa`。这些是前向数值对照，语音端到端效果须另验。

### RTX 5090 运行身份与负测

基线为实测 ComfyUI `8ff6dc384ba5c410266b40e137799e049459d4f2` 和 T8 `1ff425ece89ef9824f58f0e4dbfb057991814e88`，沿用已审核的宿主 `ops.py` 变更，仅在独立舞台复制和应用。完成候选 T8 副本准备、26 文件绑定和两套资产的实物预检。两个只读负测均返回退出码 2：

- 把文件大小相同的历史 best100 指定为本候选，因缺少匹配的注册标记被拒绝。
- 把真实注册文件与错误 SHA256 配对，因注册 SHA256 不匹配被拒绝。

首轮真实整图开启自建服务并收到原版任务 ACK，日志确认原版 GPT 与 codec 开始加载。首次构建中文分词 FST 时只读查询超时，HI 和回切未提交。保留首轮失败报告 SHA256 `917356c675964480662fe8917343a109065811b23747abaecedd46a64540ff33`。自有服务进程已退出，原服务实时回读 HTTP 200、队列 0/0。第二轮使用全新隔离舞台和端口，运行源码 `9ddda1ef97278e64f0a9ff3d875bf2a13557ec76`。修复只处理 ACK 后自有服务的只读 GET 超时，保留单次 POST、原时限与资源监控。复测恢复了两次只读超时并完成全部三轮，控制器退出码 0，观测总耗时 71.319 秒。

### Hindi 冻结 TEST 诊断

使用已有合法 Hindi TEST 8 条、2 位说话人的同语种录音与不同 clip 的配对 prompt，参考音频为 24 kHz。全体输入在执行前固定，原版与候选使用同一 greedy 参数、seed 1234、KV cache 和 512 语义 token 上限。8 条全部尝试，各只生成一次。

| 模型 | 已生成并回读文件 SHA | 失败 |
| --- | --- | --- |
| 原版官方 `43a8…19d85` | 3/8 | 5 条在单段模式下需要分段或未满足 token framing 检查。 |
| 新完整 GPT `e87e…37943` | 2/8 | 5 条命中相同 token 检查，另 1 条触及 code 上限而被标记为不完整。 |

两组都**未通过 P0 完整覆盖门槛**。短句可生成是工程证据。既有单段工具的覆盖缺口应在目标工作流以分段实测解决，命中上限的候选失败须复测和记录。真实 TEST 结果不回流选模。

固定 Whisper small 在 H200 上完成校准诊断。实际 ASR 读入 24 条计划记录，完成 13 条，包括 8 条真人参考与 5 条生成音频。11 条源合成失败明确计入覆盖缺口。可直接配对的只有 2/8。

## 产品发布与交接

部署以版本为单位。每个可上线包保留一份已验候选 GPT、2.5 模型资产清单、兼容插件 commit、工作流副本、完整适用许可与验证报告。旧语日常仍走现有模型入口。产品部署应在批量验证无严重缺陷、音质签收和回滚演练完成后，以维护窗口把模型、插件和配置同时激活。

上线先用一台实例或不超过 5% 流量，至少观察 24 小时，并覆盖 100 条旧语与 20 条 Hindi。OOM、错误模型身份、语种串路由、严重语音缺陷立即停止。回滚恢复经确认的原插件、原模型和原路由，冷启动后验实际原 GPT SHA、旧语工作流、音频和队列，目标 15 分钟内恢复接单。生产操作阈值见[验收方案第 6 节](REPLACEMENT_ACCEPTANCE.md#6-上线停止与回滚)。

GitHub 保存源码、下载与校验步骤、候选注册及公开汇总。HF 公开 adapter ZIP 和与候选对应的验收记录。完整 GPT 以独立版本在后续质量与分发审签合格后发布。私人录音、原始转写、盲评音频、原始日志留在受控目录。
